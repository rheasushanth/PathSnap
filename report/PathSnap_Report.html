1. Executive Summary & Problem Formulation

PathSnap is a high-precision, distributed map-matching and trajectory reconstruction platform designed to resolve the canonical inverse problem of urban navigation: reconstructing the true chronological sequence of road segments (arcs) traversed by a vehicle from noisy, asynchronous GPS point observations.

Three fundamental spatial invariants govern every design decision in the PathSnap architecture:

  • Fact 1 — Disconnected, Private Road Networks: Inspection of the 90 trajectory datasets reveals that each trip occupies a completely independent geographic coordinate bounding box spanning from Western Europe (Germany: 49.8°N, Austria: 47.7°N) to Central Eurasia (Russia: 56.8°N). Crucially, 89 out of the 90 road networks are topologically disconnected (median 19 connected components). Arc IDs are strictly local to each trip graph. Consequently, a global arc-ID multiclass classifier is mathematically impossible; features and models must operate strictly over candidate invariant relationships.
  • Fact 2 — Trajectory Representation Mismatch: The provided ground truth .route files do not provide per-observation labels; rather, they specify a sparse, sequence-level chronological progression of traversed arc IDs (e.g., 123 road arcs for 1,354 GPS points in trip 00000007). PathSnap formulates a monotonic Dynamic Programming (DP) route-to-track alignment with spatial outlier rejection (>100m) to generate verified per-point training targets.
  • Fact 3 — Candidate Ranking Formulation: Each observation is mapped to a set of spatial arc candidates. The machine learning model acts as an invariant binary candidate ranker, predicting the likelihood that candidate arc ak is the active ground truth. The calibrated posterior probability directly serves as the emission probability in a global Hidden Markov Model (HMM) solved via the Viterbi algorithm.

2. Exploratory Data Analysis & Spatial Preprocessing

The training partition contains 80 trips yielding 1,204,862 observation-candidate pairs, while the held-out student-test partition contains 10 trips comprising 130,768 pairs. Analysis of temporal intervals reveals that 97.2% of consecutive GPS timestamps are spaced exactly at 1.0 second. However, significant telemetry dropouts exist (e.g., a 210-second blackout in trip 00000065 and a 32-second tunnel gap in 00000076), necessitating adaptive temporal relaxation in the sequence decoder.

2.1 Coordinate Projection Justification

Because trajectories span latitudes from 44°N to 57°N, naive Euclidean distance computed directly on degree coordinates causes severe distortion (longitude scaling varies as cos(φ), introducing up to 40% distance error). Furthermore, UTM projections cannot be globally applied across zones 32U through 40V. PathSnap implements a per-trip Local Equirectangular Metre Projection centered at each track centroid (λ0, φ0):

x = R · (λ - λ0) · cos(φ0),   y = R · (φ - φ0),   where R = 6,371,000 m

This projection maintains sub-meter spatial accuracy across the geographic extent of each individual trip (<50 km) while executing tens of millions of segment projection operations with high efficiency.

2.2 Spatial Anomaly Detection (Datum Offsets)

Automated spatial auditing revealed two major anomalous trips: 00000054 and 00000033, which sit with constant geographic systematic offsets of ~118.4 m and ~67.2 m away from their nearest road network elements. This indicates an uncorrected geodetic datum translation (e.g., WGS84 vs local Pulkovo 1995/SK-42 coordinate shifts) in raw instrumentation. PathSnap flags such anomalies in its label quality audit.

3. Machine Learning Model Zoo & Empirical Evaluation

To ensure comprehensive model diversity, PathSnap evaluated five distinct machine learning model families representing linear, instance-based, bagging ensemble, gradient boosted decision tree, and neural network inductive biases.

3.1 Cross-Validation Protocol (Preventing Spatial Leakage)

Strict Trip-Grouped Splitting: In compliance with rigorous spatial data science, models are evaluated using GroupKFold(n_splits=5) partitioned strictly on trip_id. Random observation splitting places adjacent points from the same trip into both train and test folds, introducing massive intra-trip autocorrelation leakage and artificially inflating test metrics.

Primary Metric — Observation-Level Top-1 Accuracy: Because candidates occur in a ~8:1 negative-to-positive ratio, standard point-wise accuracy trivially scores ~87% by predicting all-negative. Observation-level Top-1 Accuracy evaluates the true operational goal: grouping candidate probabilities by \((trip\_id, obs\_idx)\) and checking if the argmax candidate matches the ground truth aligned arc.

3.2 Detailed Analysis per Model Family

  • HistGradientBoosting (Best Performer): Achieved the highest held-out test Top-1 accuracy (0.8518), highest Macro F1 (0.9157), and lowest Log Loss (0.1079). Binned histogram split evaluation handles non-linear feature interactions (such as perpendicular distance ratios vs bearing angle differences) with superior calibration and inference latency of 0.57s.
  • Random Forest (Bagging Ensemble): 120 trees with balanced subsampling achieved 0.8428 Top-1 accuracy and 0.8991 Macro F1. Bagging reduces candidate ranking variance effectively but produces uncalibrated probabilities near 0 and 1, requiring clipping prior to HMM emission scoring.
  • Multi-Layer Perceptron (Neural Network): Scaled (64, 32) architecture with ReLU activations and early stopping achieved 0.8369 Top-1 accuracy. Captures smooth continuous boundaries but requires standard scaling and has higher sensitivity to class imbalance than tree ensembles.
  • Logistic Regression (Linear / Probabilistic): Scaled linear model with balanced class weighting scored 0.8310 Top-1 and 0.8261 Macro F1. Underfits complex directional interactions (e.g. sharp turns and parallel bidirectional streets) due to linear decision surfaces.
  • K-Nearest Neighbors (Instance-Based): Distance-weighted KNN (k=25) scored 0.8241 Top-1. While achieving competitive local representation, KNN suffers from extreme O(N) inference cost (30.7s inference time, 3086 μs/row), rendering it impractical for live distributed deployment.

4. Bayesian Hyperparameter Optimization

Hyperparameter tuning was conducted using Bayesian Optimization via Optuna's Tree-Structured Parzen Estimator (TPE) over 25 trials on a group-stratified subset of 40 trips (647k rows). Unlike grid or random search, TPE models the conditional density P(x|y) of the objective function (Observation Top-1 Accuracy) using Parzen kernel estimators, actively concentrating search trials in promising hyperparameter regions.

5. Spatial Hidden Markov Model & Viterbi Decoding

The classifier alone evaluates each observation independently, frequently selecting disconnected parallel arcs or causing the vehicle to "teleport" between consecutive timestamps. PathSnap solves this via a global sequence formulation based on the Newson & Krumm HMM framework:

  • Hidden States: The spatial candidate arcs generated for observation t.
  • Learned Emission Log-Probability: ln P(ot | at) = ln(p̂clf + 10-12), where p̂clf is the posterior probability from our tuned HistGradientBoosting model.
  • Spatial Transition Probability: Evaluates physical travel plausibility between candidate arc u at step t-1 and arc v at step t:
Δ = | d_gps - d_road(u, v) |,   ln P(v | u) = - Δ / β

where dgps is great-circle haversine step distance, droad(u, v) is the exact road network shortest path distance computed via Dijkstra search from projected arc positions, and β = 20.0 m is the decay scale factor.

Handling Disconnected Components: Because 89 of 90 networks are disconnected, unreachable road pairs receive a robust finite log-penalty (-20.0) rather than -∞, preventing decoder collapse. In commit 89c6d29, transition lookups were accelerated 25× by employing a trip-level 99th-percentile GPS distance Dijkstra cutoff cache.

7. System Architecture & Distributed Two-Laptop Deployment

PathSnap was built from ground up to fulfill the rigorous hackathon live demonstration requirements, operating across a distributed two-laptop network architecture:

Figure 8: Distribution of Top-1 Accuracy gain per evaluation trip under Viterbi decoding.

7.1 Server-Side Inference Engine (Laptop 1 — FastAPI)

  • Runs uvicorn api.main:app --host 0.0.0.0 --port 8000. Binding to 0.0.0.0 is required for LAN connectivity across hardware nodes.
  • Exposes GET /health, GET /trips, GET /models, and POST /predict/{trip_id}.
  • Lazy Model Cache: Models are indexed via artifacts/models.json and cached in memory upon first query, maintaining minimal RAM overhead.
  • Zero Ground-Truth Leakage: Ground truth label arrays remain strictly server-side for real-time metric computation; only reconstructed path geometries, arc IDs, and aggregate evaluation metrics are emitted over the wire.

7.2 Client-Side Evaluator Interface (Laptop 2 — Streamlit)

  • Runs streamlit run ui/app.py --server.port 8501 with configurable LAN target address and automated IP normalisation.
  • Dynamic Evaluator Model Selection: An interactive dropdown lists all five models annotated with their measured student-test Top-1 scores.
  • HMM Decoding Toggle: Allows the evaluator to toggle Viterbi sequence decoding on/off live, observing real-time accuracy and continuity jumps.
  • Interactive Folium Canvas: Visualizes the reconstructed vehicle path over open street tile imagery with sub-second round-trip latency.
